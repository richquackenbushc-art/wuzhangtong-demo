# 「无碍通」无障碍出行 Web 应用产品策划案

## 项目定位

无碍通是一款面向肢体障碍人士、视障人士、志愿者与普通市民的公益出行 Web 应用。它用众包上报看见城市无障碍问题，用安全路线帮助用户避开风险，用互助接单连接附近志愿者，并把聚合数据反哺城市治理。

## 核心痛点

- 无障碍设施状态变化快，公开数据往往不够新。
- 普通导航只关心距离和时间，很少解释台阶、围挡、坏电梯、盲道占用等风险。
- 求助信息分散在社群里，附近志愿者不一定能及时看到。
- 城市治理部门缺少可持续、可核验、可视化的问题线索。

## 用户画像

- 小云，轮椅使用者：需要避开台阶、施工围挡和损坏坡道，出行前希望知道路线风险。
- 阿林，视障用户：需要大字、高对比、语音播报和清晰的下一步方向提示。
- 佳佳，普通市民：愿意随手拍上报障碍，但希望流程足够简单、有反馈。
- 老周，志愿者：愿意接附近求助，需要明确地点、需求、状态和完成反馈。

## 四层功能

1. 众包数据层：随手拍上报障碍，AI 分类后由用户确认，形成热力数据。
2. 工具层：在地图上展示安全路线与最短路线对比，说明绕开的风险。
3. 社群层：发起求助、附近志愿者接单、状态流转、评价闭环。
4. 治理层：数据墙呈现问题类型、热点区域、处理趋势和志愿服务效果。

## 地图与预定能力验证

首期地图底图固定使用 OpenStreetMap，开放范围限定为北京市中心演示区域。这样不依赖第三方地图 Key，适合比赛演示和本地离线兜底；后续可在地图适配层增加更多城市。

“预定/接单”不是地图 SDK 的内建业务能力。地图负责底图、定位、路线、POI 和地理编码；预约求助、志愿者接单、订单状态和评价由应用业务层实现。首期 Demo 使用 OpenStreetMap 北京区域底图和预置数据。

## 演示故事线

1. 数据墙开场：城市里存在盲道占用、坏电梯、台阶和围挡等高频问题。
2. 用户输入目的地：系统生成最短路线和安全路线。
3. 安全路线解释：展示多走距离、避开的障碍数量和风险等级。
4. 模拟导航：沿路线推进，靠近风险点时用视觉提示和文本播报提醒。
5. 随手拍上报：上传/拍照后 AI Mock 分类，用户确认并获得积分。
6. 热力图更新：新问题进入地图和数据墙。
7. 一键求助：用户发起求助，志愿者在接单大厅接单。
8. 完成评价：订单状态闭环，志愿服务数据增长。

## 功能取舍

- 做完整：响应式首页、路线对比、模拟导航、随手拍、互助接单、设施查询、数据墙、PWA。
- 做 Mock：AI 图片识别、实时定位、实名认证、短信/推送、云数据库实时监听。
- 做兜底：OSM 底图加载失败时保留示意地图和文本列表；定位失败时使用北京预设起点；接口失败时使用种子数据。

## 合规边界

- 位置和照片属于敏感信息，Demo 默认不上传真实云端。
- 页面明确展示路线为众包辅助建议，不承诺绝对安全。
- 志愿者端只显示求助所需信息，不展示残障类型等敏感标签。
- 演示数据与真实用户数据隔离。
